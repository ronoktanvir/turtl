# Independent read-only app evidence

`collectors.ts` exports `appStateHandler` and `errorWindowHandler`. They run as separate existing runner steps, keyed and purposed `collect_app_state` and `collect_error_window`. App state GETs `/health`, `/flags`, and `/revision`; error window independently GETs `/errors`. Neither collector runs the journey check, memory recall, preferences, augmentation, or any protected-app write. App-state reads may overlap within their collector; the existing scheduler owns concurrency between collector attempts.

Every required read must return HTTP 200 and validate before its collector can succeed. Booleans preserve `false`. Counts are finite, nonnegative safe integers, failed plus successful bookings equals total, and error rate agrees with the counts. Windows have finite ordered nonnegative bounds, typed truncation, and a positive sample limit when supplied. Error samples require nonempty codes and steps with timestamps inside the observed window; they cannot exceed the failed count or be empty when failures exist. A capped error sample need not contain every failed booking. Optional returned metadata must also be valid. Unknown facts stay absent, never false or zero. Invalid or unavailable reads record failure evidence and return a failed handler result without a successful snapshot. Responses are reduced to known fields; credentials and full raw bodies are not emitted.

## Attempt output, version 1

Each successful attempt's direct `output` is an `EvidenceSnapshot`:

- `version: 1`, `collector`, `caseId`, `stepId`, and `attemptId` identify the exact producing attempt.
- `facts` contains exactly its collector's existing fact keys, and `missing` is empty on success.
- `revision` identifies the source deployment and a source-reported commit/build if available.
- `evidence` contains `{ id, kind, sourceRef, observedAt, environment, revision }` entries referencing rows written through `evidenceRow` and `protectedApp.records.addEvidence` for that same case, step, and attempt.
- The error collector also includes `window: { since, until, truncated, sampleLimit? }` from `/errors`.

App-state facts are `health.ok`, `flags.recommendationsEnabled`, and `app.revision`. Error facts are `errors.totalBookings`, `errors.failedBookings`, `errors.errorRate`, and `errors.topCode`; the latter is the most common code in the returned error sample, or `none` only when the observed failed count is zero.

Each evidence row uses only metadata from its own source. A validated returned `environment` takes precedence over the configured `protected-app` source identity. A response without revision gets `revisionOf(null, base)`: the known source deployment host, not an invented commit. In particular, errors never borrow the parallel app-state revision, and individual health/flag rows do not borrow the revision endpoint's build. App-state snapshot revision comes from `/revision`; error snapshot revision comes from `/errors` or its known deployment identity.

## Canonical gather join

`context.ts` exports `readAppEvidence(ctx, input, context): Promise<AppEvidence>`, matching `handoffs/seams/gather-evidence.md`. It returns `{ facts, missing, revision, refs, readCount, sourceCount: 4 }`. `readCount` counts successfully observed sources, not facts. Canonical gather still owns its separate journey check, journey evidence, recall, preferences, and context augmentation, and still emits its existing downstream `{ facts, recall }` contract.

For a collector graph, the reader consumes only the exact two parents in `input.parents`, pinned by `input.attempt.inputRefs`. It requires the canonical gather key/purpose, both exact collector keys/purposes, done parent steps, done consumed attempts, matching case/step/attempt IDs, valid version-1 outputs, and evidence whose ownership and every recorded provenance field match `context.evidence`. It never substitutes a parent's newer current attempt or re-fetches app evidence. Malformed, mixed, skipped, missing, wrong-role, or unpinned collectors fail closed. The existing runner must keep accepted terminal attempt outputs immutable; late diagnostics belong separately, not in consumed output.

Existing investigate and plan handlers select evidence by gather attempt ID. `records.ts` therefore exports the internal `projectEvidence` mutation, which atomically revalidates the join's exact consumed snapshots against stored attempts and evidence, then inserts or reuses a gather-owned projection of each original row. Projections preserve kind, title, body, URL, the exact original observation time, environment, and revision. Their deterministic `sourceRef` is `Derived from evidence/<original-id>; stepAttempts/<consumed-parent-id>; <original HTTP source>`. The mutation's transactional evidence-index read makes repeated or concurrent invocations idempotent per gather attempt and original evidence ID. Originals are never changed. Reader refs contain originals and projections; projections are not new observations and do not increase `readCount`. Conflicting source environments, deployment identities, or reported commit/build revisions fail closed; a deployment-only revision remains unknown rather than borrowing another source's revision.

Legacy persisted graphs without any collector steps/dependencies retain four fresh GETs and partial-read semantics. Their readable `missing` strings describe unavailable or malformed reads; evidence rows describe those failures rather than asserting unknown health is false. Cases without journeys retain the original gather placeholder outside this reader. No migration or backfill is needed: existing attempts remain readable, while newly selected monitored templates use the fixed fork/join graph. Sample/dev templates remain unchanged.

## Verification and deployment

Run the pure, transpiled tests with `node --test convex/evidence/snapshots.test.mjs` and the repository typecheck with `npx tsc --noEmit`. Tests mock HTTP and runner context; they make no external requests. They cover source validation, missing-versus-false facts, versioned outputs, collector independence, failure evidence, exact parent pinning, source-role rejection, provenance equality, no replacement reads, and legacy partial reads.

`tests/evidence-local.integration.mjs` exercises the real Convex scheduler against a deterministic localhost HTTP server. Start an anonymous local backend with `CONVEX_AGENT_MODE=anonymous npx convex dev`, decline optional AI-file setup, and enable `DEV_TOOLS_ENABLED=true` and `EVIDENCE_LOCAL_PROOF=true` on that local backend only. Set its `PROTECTED_APP_CONTROL_SECRET` to the public fixture value `local-evidence-fixture`. Do not copy provider keys or configure `PROTECTED_APP_URL`: monitor polling and outbound services are unnecessary. The harness reads only `.convex/local/default/config.json`, targets its loopback port, and never prints its generated admin credential. `localProof.ts` exposes only internal fixtures, refuses non-local backends, requires both switches, and rejects non-local HTTP sources. Before inserting anything it also refuses configured API keys, GitHub credentials, Keiki/Revyl configuration and the global monitor URL, so these local fixtures cannot initiate provider work or alerts on a credentialed backend.

Run `node --test tests/evidence-local.integration.mjs`. It checks overlapping actual collector requests/attempts, a blocked join, separate evidence/output, one-branch retries, a forced real timeout callback followed by a late HTTP result, immutable accepted outputs, idempotent projections, exhausted/malformed required reads, skipped required collectors, a disconnected subscribed client, approval and after-action verification, and legacy/sample/no-journey paths. It also reruns `memory/dev:prove` on the isolated backend. The mock contains no real customer data and writes only its own local flag. Device verification remains explicitly uncovered without Revyl credentials and cannot establish verified recovery memory. `EVIDENCE_PROOF_OUTPUT` optionally saves a local proof summary outside the repository.

`tests/workflow-evidence.test.mjs` covers the terminal-output corruption regression, fixed templates, six-card grouping and topological/dependency ordering. UI adapter and 320/375/390px keyboard/layout tests are described in `tests/workflow.md`. Fixture rendering is not proof of backend concurrency; connected render evidence and scheduler timestamps are separate checks.

Deploy the additive purpose/schema/handler/template changes and reader adapter together only after authorization and after the owner-learning parent change. No migration, in-flight rewrite, credential change, or shared deployment is part of this module. New monitored cases receive the fork; already-persisted case graphs keep their original template. The optional `stepAttempts.lateResult` field stores late diagnostics without changing accepted output, input refs, status or completion time.
