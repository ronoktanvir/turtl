# Tests

Every suite here uses `node:test`. Nothing in them calls a real vendor: OpenAI, Supermemory, Capy, GitHub, Apple, Resend, Expo's push service and Revyl are stand-ins or recorded responses, so a passing test proves turtl's side of a call, not the vendor's.

```sh
npm run typecheck   # the app and convex/
npm run test:ci     # every *.test.mjs that needs no browser (what CI runs)
npm run test:ui     # every *.test.mjs, including the two browser tests below
```

## Backend functions without a server

Most backend tests load the real modules from `convex/` through `tests/fixtures/convex-memory.mjs`: relative imports follow the real files, `convex/_generated` is a stand-in, and an in-memory database answers only through the indexes the schema declares and writes only the fields it names. `withEnv` sets environment variables for one test, which is how a suite runs the same function once with accounts on (`AUTH_REQUIRED=true`; any value but unset, empty or `false`) and once as the single-owner demo.

Accounts mode is covered this way:

- `access-rules.test.mjs` runs the public functions against a copy of every table with a fake caller: another account's project, case or row reads as missing and writes refuse, and the demo behaves as before. `access-coverage.test.mjs` parses every module and fails for a public query, mutation or action that does not ask `convex/access.ts` who is calling, or that is not made with the builders in `convex/functions.ts`, which refuse every call when a demo deployment holds an account. `access-client.test.mjs` covers the app's side: owner decisions without a passcode in accounts mode.
- `accounts.test.mjs` runs sign-in against `fixtures/auth-stand-in.mjs`, a stand-in for GitHub's OAuth pages, Apple's keys and token endpoints, and Resend: every way an Apple token is refused, nonce replay, the password flows and their words.
- `email-codes.test.mjs` performs the attacks on emailed codes against the same stand-in and a stand-in for Convex Auth that shares turtl's in-memory database: 1,000 wrong reset codes leave the owner's working, five emails a day to an address with the newest always working, the wrong-password lock cleared by a reset, a code redeemed once, a password account held at Check your email until it confirms, throwaway sign-ups unable to fill the Apple, GitHub or confirmation ceilings, the sweep of unconfirmed accounts, and the operator's override. It also holds that a link carries only the code (a reset link for one address, completed with another, changes nothing; a confirmation link someone else sends confirms nothing), that the phone remembers the address it asked to reset for a code's life, that one email domain stops at its share of sign-ups while another's still pass, and that `EMAILS_PER_DAY` refuses in plain words while a code already sent keeps working.
- `ended-sessions.test.mjs` and `sign-out.test.mjs`: a token whose session has ended reaches nothing, GitHub's actions included, and signing out removes the phone's push registration.
- `consent-gate.test.mjs` and `consent-ui.test.mjs`: nothing reaches an AI service until the account says yes, Keiki and the council's Anthropic and Google models are refused with accounts on, taking it back stops the next call, the list comes from `store/data-practices.json`, and no file calls `fetch` past the gate. `spend.test.mjs`: the monthly model allowance, the daily coding-agent limit, the customer-report allowance and the deployment's ceilings. `shared-spend.test.mjs` performs the attacks on the deployment's shared daily ceiling (each account's daily shares; the reserve for outages, which admits only an outage the monitor raised on a real project whose check had passed for a day, of an account over 14 days old; a practice app's own allowance), and `shared-turns.test.mjs` the attacks on shared crons (the monitor's schedule, pull-request and preparation syncing) at the scale the security review names.
- `account-deletion.test.mjs` fails for any table in `convex/schema.ts` that account deletion neither removes nor lists as exempt with a reason, and runs the deletion job for one of two accounts over a copy of every table, with stand-in servers for Supermemory (`fixtures/supermemory-stand-in.mjs`) and Apple and a GitHub disconnect that fails once: afterwards nothing of the first account is left and the second is untouched.
- `project-secrets.test.mjs` and `watched-app-credentials.test.mjs`: control tokens and coding agent keys are sealed, never returned, and sent only to their own project's address; no deployment secret is sent to a project.
- `github-app.test.mjs` and `github-connect.test.mjs` run `convex/github` against a stand-in for GitHub's API and the person's browser (`github-harness.mjs`, `scripts/github-app/stub.mjs`): the app JWT, installation tokens, webhook signatures and replays, Connect GitHub with a forged installation id refused, and disconnect. `github-push-access.test.mjs` adds the permission rules: only repositories the person can push to are linked, GitHub is asked again before a merge or coding-agent work, and only an installation on the person's own GitHub account is uninstalled.
- `push.test.mjs` runs `convex/push` against `fixtures/expo-push-stub.mjs`: what a push may say, who receives it (only phones whose session is alive), refusals across accounts.
- `practice.test.mjs` runs `convex/practice`: two accounts' practice apps apart from each other and from the demo's booking app, the routes answering only to their own project's token, the daily limit on breaks. `practice-words.test.mjs` keeps a practice app's screens from reading as if it had customers or code.
- `not-answering.test.mjs` runs the monitor minute by minute against stand-ins for an app that stops answering: a quiet try (no response, or 500 or above with no result) counts on a journey check that has passed before and anything else clears it, a request turtl did not send never counts, a 404, 401, 429 or redirect is unreadable and counts for nothing either way (it neither opens a case nor keeps one open, and an open case it leaves with nothing to read closes as turtl no longer able to tell), health and readiness checks and checks that never passed keep no count, one case opens for the project only when every countable check that gave a result or went quiet is at three and no check gave a result (one quiet check beside one with a result shows on the project and sends no push), parked and never run, the app answering closes it with a second notice, turtl's own site not answering (or answering 5xx or 429) holds the case back, and so does every other project going quiet in the same minutes, ten a day at most (with the 24-hour window running out on turtl's own clock), turtl stopping its checks closes the case with no notice, a practice project (turtl's own app) never gets one, an older round finishing late changes nothing and neither opens nor closes a case, and the single-owner demo does the same, `PROTECTED_APP_URL` unset included. `shared-spend.test.mjs` holds that such a case never reaches the outage floor or reserve.
- `owner-words.test.mjs` keeps setting names and raw errors off the screens an owner reads; `watching-truth.test.mjs`, `case-counts.test.mjs` and `case-stars.test.mjs` hold what a project and a case say to the truth.
- `bounded-reads.test.mjs` fails for a read whose size grows with the whole deployment.
- The closed demo: `access-rules.test.mjs` sets `AUTH_REQUIRED` unset, empty, `false` and other values, and with it unset on a deployment that holds an account, every public function, the runner, the monitor, customer reports, the permission gate and push delivery refuse; `closed-demo.test.mjs` does the same for GitHub's pages and webhook. `access-rules.test.mjs` also refuses turtl's own site and API as a project's live app, except a practice project under its own path.
- `redact.test.mjs` and `redact-review.test.mjs` (RC-22): ordinary code comes through the masking unchanged, planted secrets and secret files do not reach what would leave for OpenAI or Supermemory, including through the onboarding inspection (`fixtures/realistic-repo.mjs`).

## On a local Convex backend

The `*.integration.mjs` files repeat the main paths in Convex's own runtime, scheduler and `fetch`, on a local anonymous deployment (`npx convex dev --local-cloud-port <port>`), with stand-ins served on local ports. Each refuses to run against anything but a local backend, and they are not part of `npm run test:ci`. See the comment at the top of each: `push-local`, `project-secrets-local`, `evidence-local`, `evidence-collectors` and `not-answering-local` (a stand-in app stops and starts again, in the demo and with accounts on). Account deletion's local proof is `scripts/account-deletion/prove-local.mjs`, emailed codes' is `scripts/email-codes/prove-local.mjs`, the practice project's is `scripts/practice/prove-local.mjs`, and Connect GitHub's is under `scripts/github-app/`. Those that also show the single-owner demo show it on a backend with no account first, and end with its refusal once one exists.

## UI regressions

Start the example UI with `EXPO_PUBLIC_DATA_SOURCE=example npx expo start --web --port 8081`, then run `npm run test:ui`. This explicit override also works when a local Convex setup has written a backend URL to `.env.local`. Do not set a conflicting data-source override in another local environment file.

The citation check (`inline-citations.test.mjs`) uses Chromium at a 390px viewport. Set `CHROME_PATH` when Chrome is not installed at a standard Linux or macOS path; set `UI_BASE_URL` to test another local preview. It opens an issue's Fixes page, compares each linked paragraph against identical plain text and verifies keyboard activation without navigation. `workflow-browser.test.mjs` builds the plan graph into a standalone page; see [`workflow.md`](workflow.md).

Timing tests check the accelerated example clock independently of a browser.

The live mapping, network, action and query-client tests run without a server. They cover recorded evidence and verification, exact repository identity, owner decisions, scoped permissions, the displayed merge head, and readable failures on a lagging deployment. Their mocked action responses are not proof that an external service ran.

The voice tests load the voice rules, the talk action and the hands-free turn taking without a server. They check that a spoken approve, decline, merge or stop is answered with where its button is and never reaches a decision, the refusals (switch off, missing key, long clip, rate limit), and the work state the case chat answers "what are you stuck on" from.

The store and release tests (`store-listing`, `store-lock`, `release-config`) hold the listing, the build profiles and the release lock to the repository; `release-config` also holds the privacy manifest's data types to the App Privacy answers (`collectedDataProblems`).

`theme-kept.test.mjs` holds that the theme a person chooses is kept across launches (in the iOS Keychain on a phone, in the browser's storage on the web) and read before the first screen draws, and that dark is used when nothing is kept.

`font-files.test.mjs` holds that the two fonts load from the copies in `assets/fonts/`, never from their packages, and that each copy is its package's own file with its licence beside it. A web export puts a package's font under `assets/node_modules/`, which the web demo's host does not serve, so every screen there fell back to the browser's serif.
