# Recorded workflow verification

Run `node --test tests/workflow.test.mjs tests/workflow-browser.test.mjs` without a dev server. The browser test builds the real `WorkflowGraph`, typography, icons, and theme into a temporary standalone page. It does not mock the graph. Only unrelated routing and Android touch sounds are stubbed; the renderer uses the libraries' web implementations.

The page is clearly labelled **Local recorded-data fixture — no live collector ran**. These screenshots and assertions prove layout, literal status display, dependency edges, keyboard expansion, 44px targets, and wrapped references, not backend execution or actual concurrency. The harness uses React development mode and fails on console errors or invalid DOM-prop warnings, including SVG accessibility prop leakage. Fixtures include fan-out/join, legacy linear steps, waiting, failed, skipped, and malformed dependencies. Screenshots are saved to `~/.capy/work/workflow-screenshots`; override with `WORKFLOW_SCREENSHOT_DIR`. Set `CHROME_PATH` if Chromium is not installed at a standard Linux path.

For connected evidence, start the actual app against the intended local Convex URL in live mode. Then run `WORKFLOW_CASE_ID=<real-case-id> WORKFLOW_LABEL=<scenario> UI_BASE_URL=http://localhost:8081 node tests/workflow-connected.mjs`. This visits the real Overview and captures the recorded Plan at 320, 375, and 390px plus keyboard-opened details. It never seeds, approves, retries, or runs a collector. The script reports the observed node labels; a screenshot of two running labels alone is not proof of backend overlap. Use local scheduler/attempt records for that proof. Run separately for the case IDs that cover running collectors, a joined retry, waiting, failure, and a legacy case.

The product hook is `useWorkflow(caseId)` through `data/index.ts`. It reads `api.cases.get`, independently of approved fixes, and returns `null` in example mode. `currentAttempt.attempt` supplies the recorded attempt count, and `inputRefs`/`outputRefs` supply consumed attempt IDs and evidence pointers. It deliberately does not expose arbitrary attempt `output`, infer timing, or replace the existing post-approval Plan. Agent attribution is not part of this slice; if the dedicated graph later needs `agentRuns`, switch the query inside `data/live/workflow.ts` to `api.cases.cards` and extend the mapping there rather than coupling the graph to `caseMapping`.

## Actual local fork and retry/join captures

With the guarded local-proof backend and live Expo app already running, run `UI_BASE_URL=http://localhost:8081 node tests/evidence-connected.mjs`. This is an explicit local integration capture, not part of the ordinary UI tests. It reads the local admin key only from `.convex/local/default/config.json`, never prints it, and invokes the existing guarded `evidence/localProof:seed`/`snapshot` functions. The backend must have its local-proof flags enabled and no external provider keys configured; the server guard rejects other configurations.

The harness warms Chromium before creating unique isolated apps/scenarios. It holds the two real localhost collector HTTP responses only during running-graph captures, verifies both recorded current attempts remain running and the join remains unstarted, captures 320/375/390px without reloading between widths, and releases the responses in `finally` before the 10-second HTTP timeout. A separate scenario fails the first error-window read once, waits for owner review, and verifies the successful join consumes exactly the successful collector attempt IDs and preserves `facts`, `recall`, and canonical `context`. It never approves a fix or changes handlers. All traffic is deterministic localhost fixture traffic, not external app/device proof.

Images use the `local-connected-running-*` and `local-connected-joined-*` names in the screenshot directory. The public-safe `local-connected-proof.json` records actual case/app/attempt IDs, statuses, times, consumed IDs, and output-field presence, without credentials or arbitrary output payloads.
