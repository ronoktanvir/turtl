# What turtl does with data: an audit from the code

**Audited commit:** `c03efd4` on `build/not-answering-cases` (16 November 2026). **Scope:** `app/`, `components/`, `data/`, `theme/`, `convex/`, `protected-app/`, `package.json`, `app.json`, `app.config.ts`.

This describes what the code at that commit does, not what the product is meant to do. Every claim links to the line that proves it, pinned to the audited commit so the link never drifts. Hover a link to see the text that line must contain; `node store/check.mjs` checks every one, and lists the referenced files that changed since the audit.

The machine-readable list of outside services is [`data-practices.json`](data-practices.json). The permission screen reads it ([convex/consent/services.ts:1](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/consent/services.ts#L1 "store/data-practices.json")), and the privacy policy and the App Privacy answers should match it.

## How the audit was done

1. Listed every outbound call: each `fetch(`, each SDK client, each `process.env` name, and each `https://` literal in the scope above. `node store/check.mjs` lists any it has not seen; at this commit there are none.
2. Read each call site to see which fields go into the request and what is kept from the answer.
3. Read `convex/schema.ts` and each module's tables for what is stored, and the account deletion registry for what is removed.
4. Read each vendor's public policy on 15 November 2026 for what happens on their side. The three vendors added since (Expo, Resend, Apple) were not read for this audit.

**Not covered:** which switches are turned on in a hosted deployment (no production deployment exists yet), and anything a vendor does beyond its published policy. One fact comes from a handoff note and not from code, and is marked where it appears.

## Two modes

The backend runs in one of two modes, chosen by `AUTH_REQUIRED` ([convex/access.ts:47](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/access.ts#L47 "export function accessEnforced()")):

- **Accounts mode** (`AUTH_REQUIRED` set to anything but empty or `false`; production sets `true`): people sign in, a password account confirms its email address first, every project belongs to one account, nothing goes to an AI service before the owner allows it, and each account has spending limits. A store build refuses a backend that is not in this mode ([components/account/AccountGate.tsx:26](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/components/account/AccountGate.tsx#L26 "<AccountsOff />")), so this is what the App Store app does.
- **The single-owner demo** (`AUTH_REQUIRED` unset, empty or `false`, [convex/access.ts:46](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/access.ts#L46 "Accounts mode, unless AUTH_REQUIRED is unset, empty, or exactly")): nobody signs in, everything belongs to one owner, the AI permission answers yes without asking ([convex/consent/gate.ts:142](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/consent/gate.ts#L142 "answer: { ok: true, account: SOLO_ACCOUNT }")), and owner decisions are guarded by a shared passcode. This is the hackathon demo. It makes no accounts. On a backend that holds any account, user, or project of another owner, nothing runs in the demo's terms: every call is refused, the monitor checks nothing, reports are turned away and nothing is sent to any service until `AUTH_REQUIRED=true` is set again ([convex/access.ts:86](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/access.ts#L86 "Refuses when this is the single-owner demo and the deployment holds accounts")).

Where the two differ, this audit says so. Everything else holds in both.

## The short version

- **The iOS app talks to turtl's Convex backend** ([data/live/client.ts:20](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/data/live/client.ts#L20 "new ConvexReactClient")), and to three other places only when the owner asks: Expo, to get the phone's push token when the owner turns notifications on; Apple's own sheet for Sign in with Apple; and GitHub's pages, in a browser sheet, to sign in with GitHub or connect repositories. It has no analytics, advertising, crash-reporting or tracking library, and asks for two permissions, each after a tap: the microphone (Talk) and notifications (Turn on notifications).
- **The backend sends data to:** OpenAI, Supermemory and Capy (AI), GitHub, Revyl, Expo (push), Resend (the emails that confirm an address and reset a password) and Apple (Sign in with Apple). Convex hosts the backend and stores everything turtl keeps. The backend also calls the owner's own live app. Keiki, and the council's Anthropic and Google models, are reached only in the single-owner demo.
- **Four kinds of content go to third-party AI:** the owner's source code, case text (which can include their customers' own words), what the owner writes (messages, notes, preferences), and the owner's voice.
- **In accounts mode the owner is asked first.** One screen names each AI service it may use (OpenAI, Supermemory and Capy) and what it receives, the backend refuses every call to a service the owner has not allowed, and the owner can take it back in Settings.
- **An account can be deleted from the app,** and with it its projects, cases, reports, the copies at Supermemory, turtl's GitHub access and the Apple sign-in token.
- **Accounts collect** an email address, a name and picture when Apple or GitHub passes one on, the id Apple or GitHub gives the person, and a password hash. A password account must confirm its address with an emailed code before it reaches anything. Turning on notifications collects the phone's push token, which works only while that phone's sign-in lasts.

## Who the data is about

| Group | How their data reaches turtl |
| --- | --- |
| **Owners**: the people who install turtl | The app, their account, and the repositories and live app they connect |
| **Owners' customers**: people who use an owner's app | A report form inside the owner's app posts to turtl's public endpoint. They never install turtl and have no account |
| **The operator** | Deployment settings. In the single-owner demo also one GitHub token, one alert phone number and one watched app; accounts mode ignores those ([convex/demoSettings.ts:40](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/demoSettings.ts#L40 "export function demoOnly")) |

## Each kind of data

### D1. Account

Accounts mode only. The demo has no sign-in and files everything under one constant ([convex/access.ts:34](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/access.ts#L34 "export const SOLO_ACCOUNT =")).

- **What:** an email address; a name and a picture when Apple or GitHub passes one on; which ways the person signs in, with Apple's or GitHub's id for them; a Scrypt hash of a password; sessions ([convex/auth/schema.ts:8](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/auth/schema.ts#L8 "What they hold about a person"), [convex/auth/password.ts:5](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/auth/password.ts#L5 "import { Scrypt } from")). Apple's email and name come in its token, the name only on the first sign-in ([convex/auth/apple.ts:17](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/auth/apple.ts#L17 "Apple's own name and email for the person come in the token")).
- **Sign in with Apple:** the backend checks Apple's token against Apple's published keys ([convex/auth/settings.ts:38](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/auth/settings.ts#L38 "https://appleid.apple.com/auth/keys")), and trades Apple's one-time code for a refresh token, which it keeps, sealed with AES-GCM under `SECRETS_ENCRYPTION_KEY`, only to revoke it when the account is deleted ([convex/auth/appleTokens.ts:17](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/auth/appleTokens.ts#L17 "sealed the way an owner's secrets are"), [convex/auth/appleTokens.ts:13](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/auth/appleTokens.ts#L13 "authorization code with the identity token"), table at [convex/auth/schema.ts:25](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/auth/schema.ts#L25 "authAppleTokens: defineTable")). Without the Apple key settings no token is kept ([convex/auth/settings.ts:52](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/auth/settings.ts#L52 "export function appleClient()")).
- **Sign in with GitHub:** through the same GitHub App that reaches repositories ([convex/auth.ts:29](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/auth.ts#L29 "GitHub({ allowDangerousEmailAccountLinking: false")). Accounts are never merged by email.
- **Emails:** two kinds, both through Resend, only when `AUTH_RESEND_KEY` and `AUTH_EMAIL_FROM` are set ([convex/auth/settings.ts:71](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/auth/settings.ts#L71 "export function emailService()")): the code that confirms a new password account's address, and the code that resets a password ([convex/auth/email.ts:67](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/auth/email.ts#L67 "Confirm your email address for turtl")). Each holds a turtl:// link that carries only the 20-character code, and the code itself, and works for 24 hours ([convex/auth/rules.ts:64](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/auth/rules.ts#L64 "export const CODE_LENGTH = 20"), [convex/auth/rules.ts:67](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/auth/rules.ts#L67 "export const CODE_VALID_HOURS = 24")). turtl keeps SHA-256 hashes of the code, the address and the address's domain, for one day ([convex/auth/codes.ts:213](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/auth/codes.ts#L213 "deletes the record of every email sent more than a day ago"), [convex/auth/schema.ts:48](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/auth/schema.ts#L48 "is a SHA-256 hash of the domain, never the domain")). At most 5 emails of each kind go to one address in 24 hours ([convex/auth/rules.ts:69](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/auth/rules.ts#L69 "export const CODE_EMAILS_PER_DAY = 5")), sign-ups and confirmations are capped per email domain, and `EMAILS_PER_DAY` bounds all emails together, apart from each confirmed address's first reset email of the day, which is always sent ([convex/auth/codes.ts:76](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/auth/codes.ts#L76 "first reset email of a UTC day stands outside the pool"), [convex/auth/settings.ts:60](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/auth/settings.ts#L60 "export const DEFAULT_EMAILS_PER_DAY = 300")).
- **Confirming the address:** a sign-up whose email cannot be sent makes no account, and is told to use Sign in with Apple or GitHub now, or an email address tomorrow ([convex/auth/domains.ts:63](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/auth/domains.ts#L63 "You can sign up with Apple or GitHub now, or with an email address tomorrow.")). A password account reaches nothing until its address is confirmed; Apple and GitHub accounts count as confirmed ([convex/auth/confirmation.ts:16](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/auth/confirmation.ts#L16 "makes an account that reaches nothing")). An account never confirmed is deleted after 7 days ([convex/auth/rules.ts:71](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/auth/rules.ts#L71 "export const UNCONFIRMED_DAYS = 7")). The link opens turtl only where nothing else claims `turtl://`; another app on the phone that claims it could receive a link's code, and the code can always be pasted instead.
- **On the phone:** the session is kept in the iOS Keychain ([data/account/storage.ts:14](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/data/account/storage.ts#L14 "keychainAccessible: SecureStore.AFTER_FIRST_UNLOCK_THIS_DEVICE_ONLY")).
- **Kept:** until the account is deleted (see "How long turtl keeps things").

### D2. Owner passcode

- **Demo only.** With accounts on, owner decisions are authorised by being the owner, and setting a passcode is refused ([convex/ownerPasscode.ts:58](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/ownerPasscode.ts#L58 "if (accessEnforced()) throw new ConvexError(PASSCODE_REPLACED)")).
- **Device:** the passcode itself is kept in the iOS Keychain through expo-secure-store ([data/live/ownerPasscode.ts:21](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/data/live/ownerPasscode.ts#L21 "SecureStore.setItemAsync")), or in the browser's local storage on web ([data/live/ownerPasscode.ts:19](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/data/live/ownerPasscode.ts#L19 "localStorage.setItem")).
- **Backend:** only a hash is stored ([convex/schema.ts:47](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/schema.ts#L47 "ownerPasscodeConfig")). **Sent outside:** never.

### D3. Source code

- **What:** the contents of a repository the owner connects.
- **Collected:** in accounts mode, only through turtl's GitHub App, and only for a repository the project's owner connected to turtl ([convex/github/access.ts:41](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/github/access.ts#L41 "is not one of the repositories this project's owner connected to turtl")); the demo's deployment-wide `GITHUB_TOKEN` reads as unset ([convex/prTracking/github.ts:27](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/prTracking/github.ts#L27 "export const githubToken = () => demoOnly(process.env.GITHUB_TOKEN)")). The code map reads up to 200 source files of at most 200 kB each ([convex/codeNetwork/build.ts:23](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/codeNetwork/build.ts#L23 "const MAX_FILES = 200"), [convex/codeNetwork/build.ts:24](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/codeNetwork/build.ts#L24 "const MAX_FILE_BYTES = 200_000")). Adding a project reads up to 400 files to see what the app already has ([convex/onboarding/github.ts:5](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/onboarding/github.ts#L5 "const MAX_FILES = 400")).
- **Sent to OpenAI:** for the code map, an excerpt of each file of up to 2,500 characters within a 240,000 character budget ([convex/codeNetwork/build.ts:26](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/codeNetwork/build.ts#L26 "const DIGEST_BUDGET = 240_000"), [convex/codeNetwork/build.ts:27](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/codeNetwork/build.ts#L27 "const EXCERPT_CHARS = 2500")); when a project is added, excerpts of up to 6,000 characters within a 150,000 character budget ([convex/onboarding/inspect.ts:30](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/onboarding/inspect.ts#L30 "const EXCERPT_CHARS = 6000"), [convex/onboarding/inspect.ts:31](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/onboarding/inspect.ts#L31 "const EXCERPT_BUDGET = 150_000"), [convex/onboarding/inspect.ts:228](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/onboarding/inspect.ts#L228 "const { text } = await respond(gate, {")). Both go through the Responses API with `store: false` ([convex/codeNetwork/openai.ts:47](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/codeNetwork/openai.ts#L47 "store: false,")).
- **Secrets:** source code is sent with its secrets masked and secret files left out. Files that are secrets by nature (`.env`, keys, secrets files) are left out whole; in everything else passwords, tokens, keys and the credentials in addresses and headers are masked before any text is cut, in the map of the code and in the inspection of a new project ([convex/codeNetwork/redact.ts:5](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/codeNetwork/redact.ts#L5 "Files that are secrets by nature are left out whole, and nothing from them leaves")). Masking works by pattern and by name, so a secret of an unusual shape under an ordinary name can still get through, and UUIDs and 40-character hex strings are kept unless they sit under a secret's name. The live app's own answers are not repository content and are not masked.
- **Sent to Supermemory:** the first 30,000 characters of every file, as searchable documents in a namespace per project ([convex/codeNetwork/build.ts:28](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/codeNetwork/build.ts#L28 "const DOCUMENT_CHARS = 30_000"), [convex/codeNetwork/build.ts:273](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/codeNetwork/build.ts#L273 "const added = await addDocuments(gate, namespace, documents)")).
- **Capy:** works in the repository through its own GitHub connection when the owner approves a code change or the preparation of a new project (D5).
- **Stored by turtl:** only the map (part names, plain summaries, file paths) and, for a new project, a readiness summary with file paths. No code ([convex/codeNetwork/schema.ts:67](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/codeNetwork/schema.ts#L67 "codeNetworks: defineTable"), [convex/onboarding/schema.ts:42](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/onboarding/schema.ts#L42 "onboardingInspections: defineTable")).
- **Kept:** the map is replaced when it is rebuilt. Everything here, and the copies at Supermemory, goes when the account is deleted.

- **Not reported:** a check whose replies turtl cannot read (its route is gone, or it answers 401, 404, 429 or a redirect), which counts for nothing while the project goes on showing when it last passed (turtl cannot yet retire a check); a host that answers for a stopped app with a page below 500 (a suspended or paused deployment, a parking page, a firewall challenge); one check failing with a 5xx while another check of the project gives a result, which shows on the project but sends no push; and any project with no countable check to send (only health or readiness checks, journeys that have never passed, or journeys whose control token was removed). A project whose only readable check crashes with a 5xx is told its app stopped answering, though the app may serve other pages. A case closes as "can no longer tell" when its countable checks become unreadable or cannot be sent, even while another check still gets no response, so an owner who rotates their control token in the middle of an outage sees the case close, and no new one opens until the token is set in turtl again. The fleet check takes any reply below 500 as proof that turtl's own requests get out; that is about turtl's network, not about any one app. While turtl suspects itself, an alert can be up to half an hour late. An outage during which the checks turn unreadable for a round closes the case quietly; if they go quiet again a new case opens three rounds later, so one outage can bring more than one push, up to the daily limit.

| Everything in Supermemory | Each namespace of the account's projects is deleted whole with the account ([convex/account/vendors.ts:19](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/account/vendors.ts#L19 "each namespace the account's projects wrote to is deleted whole")); one report's copy when the owner deletes it |
| Push tokens | Notifications turned off on that phone, sign-out, a password reset or the sign-in ending, or the account deleted |
| Apple's refresh token | Revoked at Apple and deleted with the account |
| Emailed codes | Kept as hashes of the code and the address, deleted a day after the email |
| An account whose address is never confirmed | Deleted 7 days after sign-up |
| Voice recordings | Not kept by turtl at all |
| Rate-limit counters | Pruned when a new window opens |
| The record of a deletion | Kept, with only a SHA-256 of the account id, when it ran, counts, and which vendors confirmed |

**Deleting an account** ([convex/account/deletion.ts:83](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/account/deletion.ts#L83 "export const request = mutation({")): at once, every session ends, the ways to sign in are removed, the AI permission is taken back and the phones are removed. Then the job stops everything running for the account, waits 11 minutes so nothing in flight can write ([convex/account/deletion.ts:41](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/account/deletion.ts#L41 "export const SETTLE_MS = 11 * 60_000")), asks Supermemory, GitHub and Apple to delete, and removes every row from the registry ([convex/account/registry.ts:155](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/account/registry.ts#L155 "(appId) => `prefs_${appId}`")). A vendor that fails is asked again later without holding up the rest, and a stalled run is restarted by a cron ([convex/crons.ts:26](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/crons.ts#L26 "resume account deletions")). `tests/account-deletion.test.mjs` fails for a table the registry does not remove.

## What this means for App Review

Each item is a line in the [review checklist](review-checklist.md), where it has an owner and a way to check it.

1. **Secrets in source code are masked by pattern and by name.** Every path that sends repository content to OpenAI or Supermemory leaves out secret files and masks passwords, tokens, keys and credentials before any text is cut (D3). A secret of an unusual shape under an ordinary name can still get through, and customers' reports and what the owner writes are sent as they are. (RC-22)
2. **No data processing agreement is on file** with any vendor. (RC-28)
3. **Apple and Supermemory deletion, push, the GitHub App and the emails are proven only against stand-ins.** None has run against the real service. (RC-23, RC-27)
4. **Developer tools are compiled into the app** and shown only in a development build, with Expo's development mode or `EXPO_PUBLIC_DEV_TOOLS` set to `1` ([data/source.ts:12](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/data/source.ts#L12 "export function allowsDevTools")). A store backend must not set `DEV_TOOLS_ENABLED`; with accounts on the backend refuses it anyway ([convex/access.ts:307](https://github.com/ronoktanvir/turtl/blob/c03efd40233d22a2d85dbfdb1e69b95ee16647b7/convex/access.ts#L307 "export function devToolsEnabled()")). (RC-04)
